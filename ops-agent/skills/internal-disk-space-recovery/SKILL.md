# 内网磁盘空间恢复

本 Skill 只解决磁盘空间告警，不负责通用文件管理。清理是高风险动作，必须先取证、分阶段审批、逐阶段验证；后端固定命令校验优先于本文。

## 安全边界

- Shell 目标必须是 `current-server`，且当前服务器配置地址精确属于 `192.168.100.*`。`10.*`、`172.16.*`～`172.31.*`、其他 `192.168.*`、公网、域名和监控机本地均拒绝。
- 唯一允许的删除范围是 `/data/tmp/.Trash/` 的全部内容，以及必要时 `/data/tmp/` 下除 `.Trash` 外的一级目录。不得删除两个根目录本身、`/data/tmp` 下的普通文件或任何其他路径。
- 删除只允许下文两条完整固定命令。不得改写参数、添加命令、使用通配符、`/bin/rm`、脚本语言、`xargs` 或其他删除工具；不得跟随符号链接。
- 两个阶段必须分别审批、分别执行、分别验证；不得合并命令、批量处理多台服务器或因审批通过而跳过路径校验。

## 固定流程

1. 先调用 `list_skills`，加载本 Skill；未加载时不得执行 Shell。
2. 确认当前告警标签、时间和挂载点，逐条执行只读检查：
   - `df -Pk /data`，记录总量、已用、可用和使用率；
   - 确认 `/data/tmp`、`/data/tmp/.Trash` 是真实目录而非符号链接，且仍位于 `/data` 下；
   - 有界汇总 `.Trash` 占用量和一级条目数，不递归打印全部文件名。
3. 告警已恢复、证据过期、路径缺失或解析结果变化时停止，不创建目录、不改用其他路径。
4. 每次只提交一条 Shell；模型一次返回多条工具调用时按顺序逐条执行，不并发。

单任务和未显式覆盖的命令执行均使用系统配置的 `30m` 上限；不要通过延长超时绕过路径、审批或验证步骤。

## 第一阶段：清空 `.Trash` 内容

只有磁盘告警仍有效且路径校验通过时，才单独等待 Admin 审批并提交以下完整命令：

```sh
find /data/tmp/.Trash -mindepth 1 -maxdepth 1 -exec rm -rf -- {} +
```

该命令保留 `.Trash` 目录本身，只删除其直接内容及内容树。执行后独立验证：`.Trash` 无剩余条目、`df -Pk /data`、Prometheus 最新磁盘样本和告警状态。达到恢复条件就结束，不进入第二阶段。

## 第二阶段：清理 `/data/tmp` 一级目录

只有第一阶段完成后磁盘仍不足，才先用只读命令汇总一级目录数量和占用量，再单独等待 Admin 审批并提交以下完整命令：

```sh
find /data/tmp -mindepth 1 -maxdepth 1 -type d ! -name '.Trash' -exec rm -rf -- {} +
```

该命令只删除 `/data/tmp` 下除 `.Trash` 外的一级目录及其内容，保留 `/data/tmp`、`.Trash` 和直接位于 `/data/tmp` 下的普通文件。执行后重新验证目录范围、`df -Pk /data`、Prometheus 样本和告警状态。

## 停止与报告

- 任一路径/服务器校验失败、权限不足、命令超时或输出截断，立即停止。
- 第二阶段后仍不足，只报告剩余缺口和只读证据；不得清理 `/data`、日志、数据库、发布目录或其他路径。
- 删除后空间未增加时，只检查已删除但仍被进程占用等只读证据；不得重复清理。
- 只有可用空间实际增加且告警恢复，才记录处理成功。最终分开记录：触发告警、清理前数据、每次审批、实际删除阶段、清理后数据、监控恢复情况和未解决项。
